## 2. R8 Bytecode Optimization & DEX Analysis

- **Optimization Settings:**
  ```kotlin
  buildTypes {
      release {
          isMinifyEnabled = true
          isShrinkResources = true
          proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")
      }
  }
  ```
- **Results:**
  - **Single DEX Guarantee:** The entire Android Kotlin application, Jetpack Compose UI, UniFFI runtime, and AndroidX libraries compile into a single `classes.dex` of **3,251,460 bytes** (~3.1 MiB).
  - **No Multidex Overhead:** Total method count remains safely under the 65,536 limit, guaranteeing fast ClassLoader execution during cold starts.
  - **UniFFI Rules Preserved:** ProGuard rules explicitly preserve native JNI entry points and generated records (`io.github.dikshant363.pdfcraft.core.**`), preventing R8 from stripping native callback stubs.

## 3. Native Engine Performance & Compilation Strategy

### 3.1 Static Dependency Linking
- All core engine dependencies (`hayro`, `lopdf`, `boa_engine`, `rten`, `zopfli`) are statically linked into `libpdfcraft_android.so`.
- During Gradle packaging, intermediate shared libraries (`libocrs.so`, `librten.so`) generated by cargo are pruned by `CargoNdkBuild`, ensuring that **only a single monolithic `.so`** is loaded into process memory.

### 3.2 Memory Mapping & Zero-Copy Rendering
- **Page Caching:** `MobileSession` caches loaded document bytes and parsed structures in-process, preventing redundant disk reads.
- **Tile-Based Pinch-to-Zoom:** The Compose UI utilizes spatial `TileRect` requests (`session.renderPage(doc, page, scale, tile)`), rendering 256x256 or 512x512 pixel chunks on-demand.
- **Tiled Viewport Memory Bound:** At 3x zoom on a high-DPI display, memory consumption is capped strictly to visible tiles rather than rasterizing a massive multi-hundred-megabyte single bitmap.

## 4. Audio & Media Resource Utilization

- **WAV Allocation Cap:** The bounded WAV parser (`crates/automation/src/wav.rs`) caps input streams to 64 MiB and duration to 3600 seconds.
- **Single-Pass Sample Conversion:** 8-bit unsigned PCM and 16-bit little-endian samples are transformed into big-endian signed 16-bit PCM in a single pre-allocated pass, avoiding iterative vector reallocations.
- **Voice Comment Compression:** Voice comments recorded in the UI are processed at 16 kHz or 44.1 kHz, maintaining audio clarity while keeping annotation file sizes negligible (< 100 KB for typical 15-second annotations).
