# pdfcraft-measure

Layer L4 implements distance, connected-line perimeter and simple polygon area measurements in PDF user space. It uses the public measurement model in ISO 32000-2 §12.9 (measurement properties: viewports, rectilinear measure and number format dictionaries) and the measurement intents of line, polyline and polygon annotations (§12.5.6).

Measurements are ordinary Line, PolyLine or Polygon annotations with a rectilinear Measure dictionary and a normal appearance containing the numeric caption. Their scale is stored with the annotation, so changing a drawing scale does not change earlier measurements. Moving, restyling, replying to and deleting them uses the existing comment workflow.

Scale::calibrate derives a conversion from two points and a known real-world distance. set_scale appends a named rectangular page viewport, preserving existing viewports. scale_at selects the last viewport containing the first measurement vertex. Default measurements account for UserUnit; display-coordinate conversion accounts for crop boxes and page rotation.

The desktop Measure objects panel exposes all three tools, live values and coordinate deltas, 45-degree constraints, vertex cancellation, snapping, calibration and CSV export. Automation provides measure_distance, measure_perimeter, measure_area, measure_info, measure_list, measure_scale, measure_snap and measure_export. Tool coordinates and explicit units-per-point scales use physical display points.

Number formats support compound arrays, fractional display with reduction, decimal rounding and truncation, independent X/Y/distance/area units, separators, affixes and carry between units. Imported unknown entries and unchanged indirect format arrays survive edits. Viewports can be listed, updated and removed without changing earlier annotation scales.

Visible 2D snapping uses the renderer's transformed vector paths, glyph outlines, Type 3 painting, raster edges, clipping and current optional-content choices. Extraction bounds content decoding, interpreter work, clip geometry, image pixels, segments and targets; diagnostics report truncation and unsupported visibility. Intersection searches use at most 256 nearby segments. `snap` remains the small geometry-only API; `render::geometry` supplies painted page geometry.

Geospatial scales register PDF user-space positions against geographic or projected controls. EPSG and bounded WKT definitions use PROJ projections and the declared ellipsoid; GeographicLib computes ellipsoidal lengths and polygon areas. Standard LPTS/GPTS, PCSM, GCS/DCS, boundaries and preferred units are preserved. Invalid registration returns an error before modifying the document.

`three_d` reads embedded models, PDF camera views and standard linear, perpendicular, angular and radial measurements. All calculations use actual transformed model coordinates. Native and headless point constructions share the same geometry API. Add/update/remove edits preserve unknown dictionaries and detach shared storage, honor annotation flags and document permissions, and support undo and incremental save/reopen.

`three_d_camera` provides PDF projection, clipping, orbit, pan and zoom. `three_d_raster` draws transformed triangles, lines and points with a bounded depth buffer. `three_d_snap` picks surfaces, vertices, edges, point/line primitives and silhouettes in screen space, using perspective-correct edge interpolation. Internal coplanar mesh edges are excluded from silhouettes. Searches stop with an error if primitive, nearby silhouette or occlusion budgets cannot establish a result.

Automation includes `three_d_models`, `three_d_info`, `three_d_render`, `three_d_pick`, `three_d_measurements` and `three_d_measure`. Annotation/view/measurement indices are 1-based in tools. Screen picks share the preview's navigation and dimensions; model-space rays select surfaces. The desktop 3D window performs decoding, rasterization and picking in detached background jobs and discards stale results after edits. Caption placement intersects the selected annotation plane without changing the camera or picking another surface. Text uses the stored plane axes, TY orientation, markup color and zoom-invariant size; radial text uses the standard EL extension length and left-centre anchor. New point constructions orient their annotation plane toward the selected view, and Flip text up edits TY on a saved caption. Native Backspace, Escape and Delete stay with the model window while it owns the keyboard, and text fields retain ordinary editing.

Tests use contributor-original synthetic documents and exercise formatting, calibration, viewport precedence, registration, geometry, transformed picking, visibility, hostile bounds, permissions, locked annotations, undo/redo, incremental save/reopen, native clicks and CSV confinement. Acrobat-authored runtime interoperability has not been tested.
